# 설계 결정

## 성공 기준

> **언니가 한 달 뒤에도 앱을 열고 있는가.**
>
> 더 좁히면 — **언니가 손님 이름을 눌러보는가.**

기능 완성도도, 코드 품질도, 테스트 개수도 아니다. 이것 하나다.

---

## 앱이 종이보다 나은 단 하나 — 손님 이력

이름을 누르면 나온다.

```
화선언니
   3/17 (화)    염색
   1/20 (화)    펌
  11/28 (금)    염색
  ─────────────────
  총 8회 방문
  평균 7주마다 오심
```

언니는 단골이 많아 "이름만 적어도 시술이 기억난다"고 한다. **그 기억이 지금은 머릿속에만 있다.** 지나간 달력은 버려지고 작년 기록은 없다.

**앱은 사진만 계속 찍으면, 또는 예약만 계속 넣으면 저절로 쌓인다.** 언니가 추가로 하는 일이 없다.

### 왜 일반 캘린더는 못 하는가

구글 캘린더는 일정을 **글자 덩어리**로 저장한다. "화선언니 염색"은 그냥 문자열이다. 이 앱은 손님·시술·소요시간을 **따로따로** 저장한다.

**같은 정보를 넣어도 구조가 다르면 나중에 할 수 있는 게 달라진다.** 이것이 이 앱의 유일한 근거다.

---

## 핵심 원칙 다섯

**1. 종이가 원본, 앱은 거울**
언니는 하던 대로 종이에 쓴다. 통화 중엔 화면을 못 보니 벽 달력은 없앨 수 없다.

**2. 언니가 새로 하는 일은 최소한**
같은 일을 두 번 시키면 안 쓴다.

**3. 사진 판독은 부가 기능**
없어도 앱은 온전히 동작해야 한다. 이 원칙 덕분에 2단계는 "버튼 하나와 화면 하나를 얹는 일"이 된다.

**4. 데이터는 폰 안에만**
서버 없음 = 운영비 0원, 개인정보 유출 경로 없음, **개발자가 손을 떼도 앱이 안 죽는다.**

**5. 상태를 두 군데서 관리하지 않는다**
예: AI 판독의 켜짐/꺼짐은 열쇠의 존재 여부로만 정한다. 별도 스위치를 두지 않는다.

---

## 비용 문제를 푼 방법

제약이 둘이었다.

- **언니는 돈을 내지 않는다**
- **만든 사람도 영원히 낼 수는 없다**

### 해법: AI 열쇠를 설정 화면에서 입력받는다

코드에 박지 않는다. 이 결정 하나가 세 문제를 동시에 풀었다.

| 문제 | 해결 |
|---|---|
| 열쇠를 코드에 넣으면 도난 → 서버가 필요 | 열쇠가 사용자 본인 것 → **서버 불필요** |
| 개발자가 영원히 비용 부담 | 언제든 언니에게 넘기고 손 뗄 수 있음 |
| 개발자가 서비스 해지하면 앱이 죽음 | **서버가 없으니 죽을 것이 없음** |

### 기각한 대안

| 대안 | 이유 |
|---|---|
| 무료 등급 AI (Gemini 등) | 손님 이름·시술이 **AI 학습에 사용**됨 |
| 언니 폰에 AI 설치 (온디바이스) | 웹앱에서 접근 불가 → 네이티브 앱 필요. 모델 2~5GB 설치. 한글 손글씨 정확도가 크게 떨어짐 |
| 개발자 서버에 얹기 | 개인 프로젝트와 고객 데이터가 섞임. 매달 비용. 해지 시 앱 정지 |

## 웹앱을 고른 이유

| | 웹앱(PWA) | 네이티브 앱 |
|---|---|---|
| 아이폰·갤럭시 | **한 벌로 끝** | 두 벌 |
| 심사·개발자 계정 | **불필요** | 애플 $99/년 |
| **고치면** | **즉시 반영** | 매번 재설치 부탁 |

마지막 줄이 결정적이었다. **첫 앱에는 버그가 반드시 나오는데, 언니한테 매번 재설치를 부탁할 수는 없다.**

## 기각한 아이디어

나중에 같은 길을 다시 걷지 않도록.

| 아이디어 | 기각 이유 |
|---|---|
| 예약마다 앱에 직접 입력 | 종이에도 쓰고 앱에도 쓰면 같은 일을 두 번 |
| 앱으로 종이 달력 대체 | 통화 중엔 화면을 못 봄 |
| 아침 알림을 핵심 기능으로 | 언니가 예약을 놓친 적이 거의 없음 |
| 시술별로 색 구분 | 하루 5~10건이면 색 없이도 한눈에. 색이 많으면 시끄러움 |
| 음성 입력 전용 기능 | 키보드 마이크 버튼이 이미 음성 입력(개발 0줄). 통화 중엔 마이크를 못 쓰고 미용실은 시끄러움 |
| 주간 요약 뷰 | 두 달 뒤 예약을 잡는 가게에 7일 창은 좁음 → 월간 달력으로 |
| 한글 웹폰트 | 최소 1MB대. 오프라인 캐시에 부담. 시스템 한글 폰트가 이미 좋음 |
| 드래그로 예약 옮기기 | 폰에서 스크롤과 충돌. 날짜만 바뀌고 시각은 결국 폼이 필요. 44px 칸에 잘못 떨어뜨리면 조용히 다른 날로 감 |

> **되살아난 것:** "터치로 예약 시간 옮기기"는 한때 기각 목록에 있었다. 근거가 "종이가 원본이라 다음 사진이 덮어씁니다"였는데, **사진 판독을 빼면서 그 전제가 사라졌다.** [개발 기록](Devlog#전제가-사라지면-결론도-다시-봐야-한다) 참고.
